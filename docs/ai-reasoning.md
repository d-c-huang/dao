# 六十四卦与 AI 推理：情境、内外条件与验证

六十四卦可以作为组织情境的语义标签。每卦有项目编写的现代情境、专问和核验行动，并结合上下卦形成内外条件对照。实际回答的事实依据仍来自原文、数据、计算与验证。

## 构成64种有序结构的八种基础维度

| 卦 | 传统卦德提示 | 项目设计的现代提问维度 |
| --- | --- | --- |
| 乾 | 健 | 目标与假设：要解释什么，什么证据能支持或推翻假设？ |
| 坤 | 顺 | 约束与资源：可用条件是什么，还缺什么信息？ |
| 震 | 动 | 最小实验：可以先做哪一次小验证？ |
| 巽 | 入 | 分解与迭代：如何逐步处理并随证据修订？ |
| 坎 | 陷 | 风险与反例：什么情形会使结论失效？ |
| 离 | 丽 | 证据与解释：关键事实可以在哪里核对？ |
| 艮 | 止 | 停止与边界：什么算完成，何时应保留判断？ |
| 兑 | 说（悦） | 反馈与校验：谁来复核，用什么标准检查？ |

左列卦德的文本依据见 [《说卦传》资料](sources/shuo-gua.md)。右列及64卦情境是项目的现代类比，不能倒推为古代已有AI算法，也没有评测证明这些标签能提高模型准确率。

## 64种情境的选择与组合

全64卦来自`src/hexagrams.ts`，现代情境、专问和核验行动保存在`src/hexagramReasoning.ts`。可按卦名、通行卦序、情境关键词及上下卦筛选，同时选择多个情境。筛选只改变可见列表，不清除已选项。每卦的下卦用于检查内在条件，上卦用于检查外部环境；这些是本项目的提问约定，不是事实规律。

例如屯卦提示初创阶段先澄清不确定性，革卦用于检查变革的必要性及回退条件，既济关注完成后的验收和维护，未济关注尚未闭合的交接。情境中的问题与验证行动各自独立；生成器还保留原有经典阅读背景和逐卦原文链接，明确它们不是当前任务的实证依据。

## 可以怎样落到系统中

1. **提问层**：将用户任务拆成目标、约束、行动与检验项目。八卦名称只是记忆这些项目的标签，可以按问题选用。
2. **知识层**：本项目已有卦名、上下卦、爻序、原文及出处数据。以这些字段建立检索索引或知识关系，回答时返回可定位的资料。
3. **执行层**：让系统实际检索、计算或调用工具，然后核对结果并修订结论。[RAG 与 ReAct 的原始研究](sources/ai-reasoning.md)提供讨论这些方法的入口。

0、1 与卦象的一一对应说明编码结构，不自动带来可用的机器推理。将情境标签写进提示词也不等于模型已经完成资料检索或实验。

## 本页离线工具的实际行为

“六十四卦与 AI 推理”页面接收问题、可选材料及所选情境卦，调用`src/hexagramReasoning.ts`中的`buildHexagramOutline`整理提纲。基础维度保留在`src/reasoningOutline.ts`供上下卦映射使用。没有连接模型或检索服务，不上传填写文本，不把待执行步骤报告为已完成。

生成的提纲要求后续执行者：

- 先列信息缺口，再查找原始出处。
- 将用户材料保留为“待核验”，实际核验后再更新状态。
- 记录实际执行的工具或实验结果，并给出简洁的理由摘要。
- 区分有依据的结论、条件性判断和未知事项。
- 给出反例、下一步、停止条件和独立复核标准。

用户可以复制或下载提纲，再在自己使用的 AI 工具中继续操作。页面不会把待执行的步骤展示成已完成的推理过程。

## 如何评估这个框架

如要检验64卦情境框架的实际价值，应固定模型、题集、工具和评判规则，对比有无情境清单时的事实准确性、信息遗漏、引用可核对性与任务完成情况，并记录失败案例。本项目尚未进行这样的效果评测。
